# Agent 工作台 · V1 交互原型

这是分布式 Coding Agent 工作台的前端交互原型，沿用已选定的第 1 个设计方向：浅色界面、左侧导航、中间任务列表、右侧任务详情。设计参考是本次讨论生成的第 1 张工作台方案图；代码实现保留该方案的信息层级，并补充可操作的任务与环境流程。

## 本地运行

需要本机安装 Node.js 与 npm。在项目根目录执行：

```bash
npm run dev -- --host 0.0.0.0 --port 4173
```

打开 `http://localhost:4173`。无需安装 npm 依赖，也没有构建步骤。

`dist/` 内含 HTML、CSS、原生 JavaScript、本地 Tabler 图标和子集中文字体，运行时不依赖外部 CDN。`dev-server.mjs` 提供本地静态服务；图标与字体的许可文件位于各自的资源目录。

## 可以体验的流程

- **任务列表**：按状态、项目和关键词筛选，选择任务查看详情。
- **任务详情**：切换概览、改动、验证和日志四个页签；查看示例差异、检查结果和过滤日志。
- **新建任务**：填写项目、任务描述和可选完成标准，展开高级设置后可选择 Agent 与预算。
- **执行控制**：为阻塞任务补充测试数据库后继续；停止进行中的任务，并重新执行。
- **项目与执行环境**：查看项目就绪状态、模拟连接 GitHub 和添加项目；添加示例环境或切换是否接收任务。
- **PR 预览**：在弹窗内查看明确标注的“示例 PR”、验证结果与文件改动。

新创建、重试和解除阻塞后的任务会用约 **20.5 秒**演示排队、准备工作区、编码、验证、创建 PR 和完成的流程；没有可接收任务的环境时会等待。预置的正在执行任务用于展示页面状态，不会自动完成。

所有变更仅保存在当前页面内存中，刷新即恢复初始示例数据。

## 接入真实服务的边界

本项目没有真实的 GitHub OAuth、Runner 或 ACP 后端。GitHub 连接、环境注册、构建、验证和 PR 都是前端模拟，不会访问仓库、执行代码或创建真实 PR。

生产实现需要替换以下边界：

| 边界 | 需要接入的能力 |
| --- | --- |
| 任务 API | 创建、查询、取消、重试与补充上下文，持久化任务和执行记录 |
| 事件流 | 通过 SSE 或 WebSocket 同步执行阶段、检查结果、日志和 PR 状态，替换前端定时器 |
| GitHub 授权 | 用户登录、仓库访问授权，以及提交分支、创建 PR 与检查状态回传 |
| 环境注册 | Runner 注册、身份校验、心跳、能力上报和任务领取；在执行端对接 ACP Agent |
